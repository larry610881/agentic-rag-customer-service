## 共用核心敘事（兩份 deck 的前半段相同）

**主軸一句話：「人人都做得出 RAG demo，我們交付的是敢上線、可稽核、有人陪跑的那一種。」**

### 共 1｜開場痛點（1 頁）
- 訊息句：貴公司的知識都在文件裡，但找得到的人越來越少。
- 內容：三個場景——客服重複回答同樣問題／新人問資深員工／文件散在共享槽沒人搜得到。
- 業務講稿：「這三個場景，貴公司中了幾個？」

### 共 2｜為什麼多數 AI 問答專案失敗（1 頁）
- 訊息句：四成的 AI Agent 專案會被取消——死因不是 AI 不夠聰明。
- 內容：Gartner 40% 取消預測；三死因：答錯沒人知道為什麼、資安過不了關、上線後沒人管。
- 業務講稿：「先講失敗，因為我們的產品就是為了這三件事設計的。」

### 共 3｜我們的答案：一頁定位（1 頁)
- 訊息句：可稽核、可治理、可維運的企業級 AI 知識問答。
- 內容：一張圖——中間是機器人，圍繞四個環：答案可追溯／資安防護／品質監控／成本透明。

### 共 4｜十分鐘開站（1 頁）★ 新手教學賣點
- 訊息句：不需要 IT 人員，上傳文件就能開始。
- 內容：四步引導流程截圖（建知識庫 → 上傳 → 測試 → 發布）。

### 共 5｜Bot 建置精靈（1 頁）★ 壓軸功能、live demo 錨點
- 訊息句：把貴公司的文件給它，AI 顧問替你設計出第一版機器人——現場就能試。
- 內容：精靈流程圖（上傳 → 分析 → 三個問題 → 生成機器人＋測試題組）。
- 業務講稿：「這頁我不多講，等一下直接用貴公司的文件示範。」（→ 搭配 demo 腳本，見文末配套）

### 共 6｜答案可稽核（1 頁）
- 訊息句：每一個回答，都能指出依據哪份文件、哪一段、為什麼。
- 內容：Trace DAG 畫面截圖 + 檢索評分明細——**這是競品拿不出來的畫面**。

### 共 7｜資安與治理（1 頁）
- 訊息句：資安部門會問的問題，我們有現成答案。
- 內容：防護規則、prompt 攻擊防禦題組、（完成後加）發布閘門：改壞會被自動擋下。

### 共 8｜品質有人盯（1 頁）
- 訊息句：上線不是結束——AI 自動評分每個回答，異常主動告警。
- 內容：品質評估儀表板 + 滿意度回饋畫面。

### 共 9｜成本透明（1 頁）
- 訊息句：用多少、誰用的、花在哪，一張報表說清楚。
- 內容：token 用量儀表板，按部門/機器人歸因。

### 共 10｜多通路（1 頁）
- 訊息句：網站、LINE、內嵌小工具——客戶在哪就服務到哪。

## Deck A｜產品版（共用 1–10 ＋ 以下 4 頁）

定位：賣平台授權/訂閱。適合已經知道自己要 AI 客服/知識庫的客戶。

### A-11｜方案分級（1 頁）
- 內容：方案表（知識庫數/通路/品質監控深度/閘門治理），價格欄位留白由主管定。
- 三欄草案（Free 自助／Standard／Pro，含程式現值對照與業務講稿句）：見 `02-方案表-A11-草案.md`（2026-09-03）。Free 自助為新增的漏斗入口，同時作為 B-11 階梯最底層。

### A-12｜導入時程（1 頁）
- 訊息句：標準導入兩週上線（精靈開站當天可測試）。

### A-13｜實績背書（1 頁）
- 內容：公司 AI 交付效益（6 專案 11 vs 55 人月）當公司級能力背書；產品案例落地後逐步替換。

### A-14｜CTA（1 頁）
- 行動呼籲：「帶你們的 20 份文件來，一小時內看到你們自己的機器人。」（免費 PoC 場）

## Deck B｜服務版（共用 1–10 ＋ 以下 6 頁）

定位：賣「AI 導入」整體服務——RAG 機器人是入口，往上疊 AI Agent 開發與 FDE 陪跑。
與 FDE 企劃三商品完全對齊：就緒度評估（hook）→ 落地衝刺（主力）→ 轉型陪跑（長約）。

### B-11｜從機器人到 AI 轉型：服務地圖（1 頁）
- 訊息句：知識問答只是起點——同一套方法，可以複製到貴公司任何流程。
- 內容：階梯圖——RAG 知識問答 → 流程自動化（AI Agent）→ 全面 AI 轉型陪跑。

### B-12｜我們的導入方法：先診斷，不硬上（1 頁）
- 訊息句：我們的第一步是判斷你需不需要 AI——不需要就告訴你不需要。
- 內容：交付光譜圖（規範資產 → 半自動 → Agent）；呼應共 2 頁的 40% 失敗率。
- 這頁是 FDE 差異化主張的對客戶版本。

### B-13｜三個服務商品（1 頁）
- 內容：AI 就緒度評估（1–2 週）／AI 落地衝刺（6–8 週，含 RAG 機器人或 Agent）／AI 轉型陪跑（季度駐點）。範圍與交付物明確，價格留白。

### B-14｜AI Agent 開發能力（1 頁）
- 訊息句：機器人之外，我們替企業打造會執行任務的 AI 同事。
- 內容：agent 能力示意（多代理分工、工具呼叫、系統整合）＋ 平台的 agent 架構當證據。

### B-15｜為什麼是我們：FDE 陪跑模式（1 頁）
- 訊息句：我們不是交付軟體就離開——工程師駐點陪跑到真正被使用為止。
- 內容：FDE 模式一句話 + 全球趨勢一行（AWS 十億美元投入此模式）+ 我們的 SI 整合基因。

### B-16｜CTA（1 頁）
- 行動呼籲：免費「AI 就緒度快篩」——一次會議，告訴你貴公司最值得做的三個 AI 場景。

## 業務配套（deck 之外，同批交付）

1. **Demo 腳本一頁**：Bot 精靈現場示範的標準流程（要客戶帶什麼文件、示範哪三個提問、出錯時怎麼接話）。
2. **異議處理 FAQ 一頁**：「跟 ChatGPT 差在哪」「資料會不會外洩」「答錯了誰負責」「為什麼不自己用開源做」——每題三句話標準答案。
3. **一頁式 leave-behind**：A/B 各一張，客戶會後轉發用。
4. 每頁 pptx 的備忘稿寫入「業務講稿句」，讓非技術業務照著講。

## 給主管對齊的決策點

1. A/B 兩份的優先順序（建議 B 先做——B 能帶出 A，反之不行）。
2. 價格頁：放區間、放「另議」、還是完全不放。
3. Bot 建置精靈目前尚未開發——deck 先以「規劃中功能」呈現還是等做完再上？（建議：B 版先用流程圖呈現、標註 roadmap；精靈完成後補截圖並開放 live demo。）
4. 免費 PoC / 快篩的成本由誰吸收（業務費用 vs 部門投資）。
5. 公司品牌層級：這兩份要不要掛「AI 落地服務」的統一名稱（連動 FDE 企劃 Phase 3 的品牌決策）。
